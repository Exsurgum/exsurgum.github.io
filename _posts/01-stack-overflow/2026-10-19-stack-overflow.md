## 什么是栈溢出

本文中的“栈溢出”指的是**栈缓冲区溢出（Stack-based Buffer Overflow）**：程序向栈上的缓冲区写入数据时，超出了它的边界，导致缓冲区之外的内存被改写。

例如下面这个函数：

```c
#include <unistd.h>

void vuln(void)
{
    char buf[16];
    read(0, buf, 64);
}
```

`buf` 只能容纳 16 字节，但这次 `read` 调用请求从标准输入读取最多 64 字节。如果实际写入的数据超过 16 字节，就会越过 `buf` 的边界。

越界的数据可能覆盖相邻的局部变量、保存的栈帧信息，或者函数的返回地址。具体覆盖到什么，取决于程序实际的栈布局和写入长度。

这可能导致数据被篡改或程序崩溃。如果保存的返回地址能够被控制，并且满足相应的利用条件，还可能改变函数返回后的执行位置。

## 栈溢出的原理

沿用上面的例子，下面依次说明：输入怎样越过缓冲区边界、怎样影响保存的返回地址，以及返回地址被改写后怎样影响执行流程。

### 函数调用时的栈帧布局

x86-64 System V ABI 下，`call` 先把下一条指令的地址压栈，作为返回地址；被调用函数的序言再做三件事：

```asm
push %rbp          ; 保存调用者的 rbp
mov  %rsp, %rbp    ; 建立当前帧
sub  $0x40, %rsp   ; 给局部变量腾空间
```

函数返回时执行 `leave`（等价于 `mov rsp, rbp; pop rbp`）和 `ret`（弹出栈顶 8 字节作为下一条指令地址）。

以 `char buf[64]` 为例，栈上从低地址到高地址大致是这样：

```text
高地址
        ┌──────────────────┐
        │   调用者的栈帧    │
        ├──────────────────┤
        │   返回地址        │  [rbp+8]
        ├──────────────────┤
        │   保存的 rbp      │  [rbp]
        ├──────────────────┤
        │   Canary          │  [rbp-8]   （开启 -fstack-protector 时才有）
        ├──────────────────┤
        │   buf[63..0]      │  [rbp-0x40]，rsp 指向这里
低地址
```

`buf` 的起始地址和返回地址之间隔着保存的 `rbp`，开了栈保护时还隔着 Canary。这个距离就是覆盖返回地址需要的偏移。

### 越界写怎样踩到返回地址

`read` 从 `buf` 起始地址开始，按低地址到高地址连续写入。前 64 字节写满 `buf`，再往后就进入相邻区域：

- 未开 Canary 时，`buf` 之后紧接保存的 `rbp`（8 字节），再往后才是返回地址；
- 开了 Canary 时，`buf` 和保存的 `rbp` 之间还夹着 8 字节的栈保护值。

所以覆盖偏移不能只看 `char buf[16]` 里那个 16。它等于 `buf` 起始地址到 `[rbp]` 的距离，加上保存 `rbp` 的 8 字节，有 Canary 时再加 8 字节。

### ret 怎样改变执行流

函数执行到 `leave; ret` 时，`ret` 从栈顶弹出 8 字节当作下一条指令的地址。如果这 8 字节已经被我们的输入覆盖成另一个函数的地址，程序就会跳过去执行那个函数，而不是返回调用者。

进入函数时的栈状态也要对上。正常 `call` 之后，函数入口处 `rsp % 16 == 8`；用 `ret` 跳进函数时弹出的正好也是 8 字节，状态和 `call` 一致，所以简单的 ret2win 不需要额外补 `ret`。只有用 ROP 链连续调用多个函数时，才可能需要在某个调用前补一个 `ret` 调整对齐，否则 `movaps` 之类的指令会崩。

## 如何定位覆盖偏移

### 从反编译读

用 `objdump` 或 IDA 看函数序言里的 `lea` 和 `sub`，就能读出 `buf` 相对 `rbp` 的位置：

```asm
401190: endbr64
401194: push   %rbp
401195: mov    %rsp,%rbp
401198: sub    $0x40,%rsp
40119c: lea    -0x40(%rbp),%rax     ; buf 在 rbp-0x40
...
4011b3: leave
4011b4: ret
```

`buf` 在 `rbp-0x40`，返回地址在 `rbp+8`，所以覆盖偏移是 `0x40 + 8 = 72`。

### 用 cyclic 实测

反编译看不太准的时候，发一串特征字节，让程序自己崩在返回地址上：

```python
io.send(cyclic(200))
```

在 gdb 里看崩溃时的 `rsp`：

```text
pwndbg> x/gx $rsp
0x7fffffffe5a8: 0x6161616c6161616b
pwndbg> cyclic -l 0x6161616c
72
```

`cyclic_find` 和 gdb 的 `cyclic -l` 结果一致，偏移就是 72。`io.corefile` 也能自动算，但它依赖系统的 core dump 设置，WSL 默认把 core 通过管道交给 `wsl-capture-crash`，拿不到文件，所以调试器更稳。

### 误差来源

同一个源码换一种编译方式，偏移就可能变：

- 开没开 `-fstack-protector`，中间多不多 8 字节 Canary；
- 编译器给局部变量排的顺序，`buf` 不一定紧贴 `rsp`；
- 结构体 padding 和 16 字节对齐填充；
- `-O2` 之后变量被放进寄存器，栈布局整个变样。

所以偏移要么从当前二进制的反汇编读，要么实测，不要抄别人文章里的数字。

## 保护机制

| 机制 | 主要作用及其影响 |
| --- | --- |
| Canary | 在 `rbp-8` 放一个随机值，函数返回前比较；不一致就调用 `__stack_chk_fail` 终止进程。 |
| NX | 栈和堆标记为不可执行，`ret2shellcode` 失效，只能复用已有代码。 |
| ASLR | 随机化栈、libc、堆的基址；改写目标前通常要先泄露地址。 |
| PIE | 主程序也随机装载，`elf.sym["win"]` 这类地址不再固定。 |
| RELRO | Partial 时 GOT 可写；Full 时 GOT 只读，只能改返回地址或走 ROP。 |

### Canary 的两个细节

第一，Canary 的最低字节固定是 `\x00`。这是为了防止 `strcpy`、`%s` 这类按字符串处理的函数把整个值读出来——遇到 `\x00` 就停了。所以泄露 Canary 时用 `write(1, buf, n)` 这种按长度输出的函数更可靠，用 `%s` 会在第一个字节就截断。

第二，Canary 每次进程启动都不同。本地调试时记下的值，换一次运行就失效，脚本里必须现泄现用。

## 怎样修复这个越界写入

保护机制只是缓解，程序本身仍要保证写入不越界。把读取长度限制成缓冲区大小：

```c
#include <stdio.h>
#include <unistd.h>

void safe(void)
{
    char buf[16];
    ssize_t n = read(0, buf, sizeof(buf) - 1);
    if (n <= 0)
    {
        if (n < 0)
        {
            perror("read");
        }
        return;
    }
    buf[n] = '\0';
}
```

这里用 `sizeof(buf) - 1` 而不是 `sizeof(buf)`，是为了给结尾的 `'\0'` 留一个字节。`read` 不会自动补零，后续要把输入当 C 字符串用，就必须自己补，并且以返回值 `n` 为准：返回 `0` 表示读到 EOF，返回 `-1` 表示出错。

编译时再加上 `-fstack-protector-strong -D_FORTIFY_SOURCE=2 -fPIE -pie -Wl,-z,relro,-z,now`，能把大部分简单利用挡在门外，但这些都只是提高门槛。

## 常见利用思路

### 代码注入：ret2shellcode

把机器码写进缓冲区，再把返回地址指回缓冲区开头。条件是栈可执行（NX 关闭），并且知道缓冲区的运行时地址。现代题目基本不开这个口子，但理解它有助于分清“执行写入的代码”和“复用已有代码”两类思路。

### 代码复用

**ret2text / ret2win**：程序里本来就有能完成目标的函数，直接把返回地址改成它的入口。CTF 里这个函数可能叫 `win`、`backdoor`、`getshell`，也可能只是打印 flag 的一段代码。

**ret2libc**：没有现成的后门函数时，返回到 libc 里的 `system`，参数指向 `"/bin/sh"`。libc 的加载基址受 ASLR 影响，一般先用 `puts@got` 之类的已解析表项泄露一个 libc 地址，算出基址再构造第二段 payload。

**ROP**：需要传多个参数或做一系列操作时，把若干以 `ret` 结尾的短指令片段（gadget）串起来。x86-64 下最常见的入口是 `pop rdi; ret`，用来给第一个参数赋值。ROP 复用的是已有代码，所以 NX 开着也能用。

**栈迁移**：溢出空间不够放下整条 ROP 链时，用 `leave; ret` 把 `rsp` 搬到另一块可控内存（如 `.bss`），再在那里继续执行。

这些做法经常混着用。比如先用 ROP 调 `puts` 泄露 libc，再返回到 `main` 重新触发漏洞，第二段用 `system("/bin/sh")` 收尾。

两道完整的实操例题见 [01.1 栈溢出经典例题](/posts/stack-overflow-examples/)。
