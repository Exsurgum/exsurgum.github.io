在 [02.1 Shellcode 汇编语法与常用工具](/posts/shellcode-tools/) 的 `objdump` 输出里可以看到，常规写出的 `mov rax, 1` 会编出 `b8 01 00 00 00`，带出一串 `0x00`。本文按功能块整理 x86-64 下常用的无空字节、位置无关局部写法，最后用一段打印 `"hi\n"` 并退出的短代码把这些写法串起来。

## 清零与小常数赋值

### 清零寄存器

不要写 `mov rax, 0`（机器码含 4 个 `00` 字节），常用下面两种方式：

- **`xor eax, eax`**（`31 c0`，2 字节）：x86-64 架构规定，写入 32 位寄存器会自动把对应 64 位寄存器的高 32 位清零。因此 `xor eax, eax` 和 `xor rax, rax` 效果完全一样，还省掉了 1 字节的 `REX.W` 前缀（`48`）。
- **`cdq` / `cqo`**（`99` / `48 99`，1\~2 字节）：`cdq` 把 `eax` 的符号位扩展到 `edx`。只要刚清零过 `eax` 或 `rax` 里放着一个非负小整数（最高位为 0），一条 1 字节的 `cdq` 就能顺手把 `rdx` 也清成 0。

### 赋值为小正整数（1\~127）

- **`xor` + 低 8 位赋值**：先把整个寄存器清零，再只写低 8 位 `al` / `dil` / `dl`。

```nasm
xor eax, eax
mov al, 1            ; 31 c0 b0 01（4 字节，无 \x00）
```

- **`push imm8` + `pop`**：更短的写法是直接压入 1 字节立即数再弹出，共 3 字节。

```nasm
push 1
pop rax              ; 6a 01 58（3 字节，无 \x00）
```

这里要注意 `push imm8` 会按**有符号 8 位整数**扩展到 64 位：赋值 `0`~`127` 没问题，一旦超过 `127`（比如 `0x80`），扩展后最高位全变成 `1`（负数），不能直接拿来当正整数用。

### 对已有寄存器值做微调

如果两个参数相邻（比如先有 `1` 再需要 `2`），`inc` / `dec` 也能避免立即数：

```nasm
push 1
pop rax              ; rax = 1
mov edi, eax         ; rdi = 1
```

需要注意：在 32 位 x86 里 `inc eax` 只要 1 字节（`40`），但 x86-64 把 `0x40`~`0x4f` 分配给了 `REX` 前缀，所以 64 位下 `inc eax` 是 2 字节（`ff c0`），依然不含 `\x00`。

## 三种位置无关数据寻址写法

写好的字符串或结构不能写死绝对地址，x86-64 下通常从下面三种方式里选一种。

### 方式一：`rip` 相对寻址（`lea reg, [rel label]`）

上篇用过 `lea rsi, [rel msg]`，写法最直观，但有一个隐藏坑：**如果 `msg` 放在指令后面不远处，机器码里的偏移量是一个较小的正数，高位会带出 `00`**（例如上一篇 `objdump` 里的 `48 8d 35 13 00 00 00`）。

要避免 `rip` 相对寻址产生 `00`，可以把数据放在代码**前面**（用 `jmp` 跳过数据段再开始执行）：向低地址寻址时相对偏移是负数，补码高位全为 `ff`，就不会出现 `\x00`。

### 方式二：压栈构造字符串（`push` + `mov reg, rsp`）

如果只需要极短的字符串（≤ 8 字节），直接把字符按小端序压到栈上，再把 `rsp` 交给参数寄存器，省掉数据段：

- x86-64 **没有 `push imm64` 指令**：一次性写满 8 字节要先 `mov rax, imm64` 再 `push rax`。
- **写 4 字节以内的常数**：可以直接 `push imm32`（符号扩展压栈）。
- **末尾需要 `\x00` 截断时**：不能直接在立即数里写 `00`，可以先在最高位填一个非零占位字节（比如 `'A'` = `0x41`），再用右移指令 `shr` 把它挤出低位，自动在高位补出 `00`。

```nasm
mov eax, 0x0a696841   ; 小端序字节为 'A', 'h', 'i', '\n'（无 \x00）
shr eax, 8            ; 变成 0x000a6968，内存里即 "hi\n\x00"
push rax
mov rsi, rsp          ; rsi 指向栈顶的 "hi\n"
```

### 方式三：`jmp` / `call` / `pop` 跳板寻址

当需要自带较长的数据块、又不想算负数偏移时，常用 `jmp` 和 `call` 配合拿返回地址：

```nasm
    jmp short get_data
back:
    pop rsi              ; 栈顶就是 call 压入的下一行地址，即 msg
    ; ... 后续使用 rsi ...
    jmp short done

get_data:
    call back            ; 向低地址回跳（偏移为负，机器码无 \x00）
msg:
    db "hello, world", 0x0a
done:
```

要点在于顺序不能反：必须 **`jmp` 在前、`call` 在后往回跳**。因为 `call` 固定用 5 字节（`e8 + 32 位相对偏移`），如果 `call` 向前跳很短的距离，正偏移高位会带出 3 个 `00`；向低地址回跳时偏移为负，高位全是 `ff`。

## `syscall` 前后的寄存器保存

实际串起多个系统调用时，最容易忽略硬件和 ABI 规则导致崩溃或拿错值：

1. **`rcx` 和 `r11` 会被破坏**：执行 `syscall` 时，CPU 自动把返回地址写进 `rcx`，把标志寄存器 `rflags` 写进 `r11`。任何临时变量都不要存在这两个寄存器里跨过 `syscall`。
2. **返回值固定回 `rax`**：例如第一个系统调用返回了一个句柄或长度，紧接着第二个系统调用又要用 `rax` 传调用号，必须先用 `mov` 或 `xchg` 把返回值转存到安全寄存器（如 `rdi`、`r12`、`rbx`）里，再写新的调用号。
3. **传 4 个以上参数用 `r10`**：第 4 个参数放在 `r10`，不是普通函数调用约定里的 `rcx`。

## 串联示例：无空字节的输出与退出

把上面的清零、`push/pop` 赋值、栈上构造字符串和 `shr` 消零合在一起，写成一段不含任何 `0x00` 字节的 `sys_write(1, "hi\n", 3)` + `sys_exit(0)`：

```nasm
bits 64

    mov eax, 0x0a696841   ; 构造 "Ahi\n"（避免直接出现 \x00）
    shr eax, 8            ; 右移 8 位变成 0x000a6968 -> "hi\n\x00"
    push rax
    mov rsi, rsp          ; 参数 2: buf = rsp

    push 1
    pop rax               ; 调用号 1 (sys_write)
    mov edi, eax          ; 参数 1: fd = 1 (stdout)
    xor edx, edx
    mov dl, 3             ; 参数 3: count = 3
    syscall

    xor edi, edi          ; 参数 1: status = 0
    push 60
    pop rax               ; 调用号 60 (sys_exit)
    syscall
```

用 `nasm -f bin` 编出纯二进制并用 `ndisasm -b 64` 查看：

- 总长 27 字节，中间没有任何 `00`（也没有 `0a` 之外的控制符——字符串本身如果不需要换行，把 `0x0a` 去掉也能做到全无 `\n`）。
- 顺序上先准备好 `rsi` 再写 `rax = 1`，避免 `shr` 修改 `eax` 后把调用号冲掉。

## 常见踩坑小结

- **`xor al, al` 只清低 8 位**：高 56 位依然保留旧值，清零整个寄存器必须写 32 位寄存器（`xor eax, eax`）。
- **`push` 超过 `127` 会符号扩展**：`push 0x80` 弹出到 64 位寄存器后变成 `0xffffffffffffff80`；大于 `127` 的数改用低位寄存器拼接或运算得到。
- **以为 `cdq` 永远清零 `rdx`**：只有 `eax` 第 31 位为 `0` 时 `cdq` 才清零 `edx`；如果 `rax` 刚放过负数或地址高位为 1 的值，`cdq` 会把 `edx` 变成 `0xffffffff`。
- **把 `call` 写在 `jmp` 前面**：`call` 正向短跳会编出 `e8 XX 00 00 00`，引入 3 个 `\x00`；`jmp-call-pop` 必须让 `call` 往低地址回跳。
